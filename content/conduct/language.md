# Language

Always on in every OEES project. This rule has no opt-out.

This rule applies to all text that you write for people. This includes replies, plans, reports, commits, pull requests, review comments, code comments and documentation.

- In replies, questions, plans and reports, use the language that the person uses.
- In commits, pull requests, code comments and documentation, use the language that the repository uses. Do not change it to the language of the person.

The rule does not apply to code, identifiers or commands. It does not apply to text that you quote exactly: output, errors, logs, legal text and text that a person gives you. If a person asks for a different style for one text, use that style for that text only.

## English: ASD-STE100 Simplified Technical English

- Write one topic in each sentence. Write one instruction in each sentence.
- Use a maximum of 20 words in an instruction and 25 words in a description.
- Write a maximum of six sentences in a paragraph, about one topic.
- Use the active voice. Use the imperative for instructions: "Run the tests", not "The tests should be run".
- Use the simple tenses: present, simple past and future.
- Use the simple, common word: "use", not "utilize"; "start", not "initiate"; "help", not "facilitate".
- Use one word for one meaning. When you name a thing, use the same name each time.
- Use a single verb, not a phrasal verb, when one exists: "remove", not "get rid of".
- Keep the articles ("the", "a") and the verbs. Do not remove words to make the text shorter.
- Do not make a noun cluster of more than three words. Use "the timeout of the retry policy for the payment service", not "payment service retry policy timeout".
- Put the condition before the instruction: "If the check fails, read the log." Put a warning before the step that it applies to.
- Use a numbered list for steps that occur in sequence.

## Spanish: plain language to UNE-ISO 24495-1 (lenguaje claro)

Use the principles of UNE-ISO 24495-1:2024: the reader finds what they need, understands it, and can use it. Also use these rules:

- Write one idea in each sentence, with a maximum of 20 words in an instruction and 25 words in a description.
- Use the order subject, verb, object: "El script crea la rama", not "La rama es creada por el script".
- Use the active voice. Do not use the passive with "ser".
- Use the imperative for instructions, in the form of address that the person uses (tú or usted).
- Use verbs, not nouns made from verbs: "configura el servicio", not "realiza la configuración del servicio".
- Use the common word: "usar", not "utilizar" or "hacer uso de"; "empezar", not "proceder a".
- Use one term for one meaning, each time. Keep the technical terms that the team uses, for example "commit" and "pull request".
- Do not use a gerund for an action that occurs after the main verb. Do not use a double negative or a long inserted clause.
- Use a numbered list for steps that occur in sequence.
